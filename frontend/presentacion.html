BLOQUE 01 · LA DECISIÓN DE DISEÑO

SQL describe el análisis.
JavaScript lo implementa.

La elección no es que un lenguaje sea “mejor” para todo. SQL encaja mejor cuando el trabajo central es filtrar, relacionar y agregar datos.

PROPÓSITO GENERALJavaScript
const totalPorCanal = {};
for (const venta of ventas) {
  if (venta.estado !== 'completada') continue;
  totalPorCanal[venta.canal] =
    (totalPorCanal[venta.canal] || 0)
    + Number(venta.total);
}
// Faltan joins, nulos y ordenamiento
Hay que implementar a mano el recorrido y la agrupación.
→EL MISMO ANÁLISIS
DOMINIO ANALÍTICOSQL · .SQL-BI
SELECT c.nombre AS canal,
       SUM(v.total) AS ingresos
FROM ventas v
JOIN canales c ON c.id = v.canal_id
WHERE v.estado = 'completada'
GROUP BY c.nombre
ORDER BY ingresos DESC;
El motor SQL ejecuta la relación y agregación.

BLOQUE 03 · DOS PUNTOS DE CONTROL

La interfaz da feedback.
El servidor toma la decisión.

La validación del navegador mejora la experiencia, pero no es una frontera de seguridad: cualquier cliente podría llamar directamente a la API.

A
MIENTRAS SE ESCRIBE

Validación interactiva

El editor envía SQL y parámetros a POST /api/query/validate. La barra muestra si la consulta es válida.

✓feedback visible antes de ejecutar
Y ADEMÁS
B
AL EJECUTAR

Validación en backend

POST /api/query/execute vuelve a validar el SQL. Si falla, responde HTTP 400; solo después llama a pool.query().

↳la decisión confiable está en el servidor
SECUENCIAEnviar consulta → renderizar parámetros → validar → ejecutar únicamente si el resultado es válido.
